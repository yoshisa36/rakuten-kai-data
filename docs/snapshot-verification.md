# オフライン・スナップショット検証

## 対象と実行

Linux/POSIX・Python 3.12で、すでにローカルに存在するJSONの新旧ペアを検証します。スクリプトはファイルを読み取るだけで、通信、Git操作、ファイル作成・変更、コピー、予約登録、投稿、返信を実行しません。既存workflow・本番JSON・予約登録処理には変更を加えません。

```sh
python3 scripts/verify_snapshot.py \
  --source-root /local/source \
  --destination-root /local/destination \
  --path threads-analysis.json \
  --path threads-queue.json \
  --path rakuten-affiliate.json \
  --path products.json \
  --path selection-history.json \
  --source-commit 0000000000000000000000000000000000000000
```

説明用の全ゼロSHAを、取得時に別途記録したコピー元コミットSHAに置き換えてください。40桁または64桁の16進文字列を受け付けます。`--source-commit` は記録用メタデータです。ツールはGitやGitHubを参照せず、入力ファイルがそのコミット由来かどうかを検証しません。レポートは常に `source_commit_verified: false` です。

`--path` は新旧ルートからの同一相対パスで、複数指定できます。指定したファイルだけが検証対象であり、対象ファイル一覧の網羅性は利用者が確認します。別名の予約JSONには `--queue` を指定してください。このフラグは選択した全ファイルに適用されます。

## レポートと終了コード

標準出力にJSONレポートを1件出します。通常の引数・入力エラーでも例外本文や入力値を出しません。`--help` のみ説明を表示します。

各 `results` 要素には次を含みます。

- `path`: 検証対象として指定した相対パス。
- `source` / `destination`: 読み取り結果、JSON妥当性、サイズ、生バイトのSHA-256、必要に応じて固定エラーコード。
- `size_equal` / `sha256_equal`: サイズとハッシュの比較。読み取れない場合はnull。
- `json_structure_equal`: 全JSON値の比較。不正JSONの場合はnull。
- `queue`: 予約IDの妥当性、件数、集合一致、コピー先の欠落・追加件数。
- `status`: match、mismatch、invalid。

終了コードは0=全対象の完全一致、1=差異あり、2=入力不正・読み取り不可です。不正と差異が混在する場合は2を返します。両側が同じ不正JSONや重複予約キューでも成功にはしません。

整形、改行、UTF-8 BOM、キー順が異なる場合、JSON構造が一致してもバイト不一致で終了コード1になります。SHA-256はGit blob SHAとは別物です。本文、予約ID、投稿ID、未知フィールド名、差分値、ルートディレクトリは出力しません。指定パス・ハッシュ・件数は出るため、パスに秘密を入れず、レポートも運用情報として管理してください。

## JSON・予約キューの検証

UTF-8（BOM可）で読み、構文エラー、重複キー、NaN/Infinity等を拒否します。小数はDecimalで解析し、小さい差を浮動小数点の丸めで失わないようにします。過度な桁数やネスト等で解析できないものは入力不正です。

構造比較はオブジェクトのキー順を無視し、配列順と全フィールド・全値を比較します。本文・予約日時・承認・投稿状態・投稿ID・未知フィールドの追加／削除／変更が対象です。文字列と数値、真偽値と数値、整数と小数は区別します。同じ値の小数表記の違いは構造上同じ場合がありますが、バイト比較では失敗します。

`threads-queue.json` または `--queue` 指定時は、posts配列と空でない文字列reservationIdを必須とし、重複IDを拒否します。別名でもどちらかにreservationIdがあれば自動検査します。ID集合の欠落・追加は件数だけを報告します。IDは形式の業務妥当性まで検査しません。未知の予約キュー名でIDが両側とも全欠損している場合は自動識別できないため、必ず `--queue` を使います。

## パス・資源・同時更新の制約

- 信頼できるローカルのスナップショットディレクトリだけを指定してください。ネットワークマウント等を指定しないでください。OSのマウントによる通信までは検知・遮断できません。
- 相対パスはASCIIの英数字、`_`、`-`、`.`、`/`に限定し、`.json`のみ受け付けます。絶対パス、空要素、`.`、`..`、URLは拒否します。ルートにも `..` は使えません。
- ルートからファイルまで各要素をdirectory fdとO_NOFOLLOWで開き、シンボリックリンクを拒否します。対応機能がない環境は失敗します。通常ファイルのみ読み、ディレクトリ・FIFO等は拒否します。
- ハードリンク、マウントポイント、攻撃者が管理するファイルシステムを隔離するサンドボックスではありません。root指定自体は利用者が信頼境界として決めます。
- 1ファイル8MiBまで。読み取り前後のサイズ・更新時刻等が変われば失敗します。ただし複数ファイルの原子的なスナップショットや、敵対的な同時改変の完全検知は保証しません。
- 生バイトをメモリに読みます。暗号署名・真正性証明、運用鮮度、GAS側の取り込み・投稿状態、本番稼働は判定しません。

## 将来の複製検証

コピー元コミットSを固定して全対象を取得し、コピー先コミットDから再取得したローカルファイルと比較します。SとDの対応・対象一覧・検証日時・レポートは別途記録します。このツールは取得・複製・記録ファイルの保存を行いません。コピーのためにupdatedAt等を書き換えません。不一致なら切り替えず、古いキューへの自動復元・再登録は行いません。

## テスト

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tests/run_offline.py
```

人工データを一時ディレクトリに作成し、外部通信を遮断して全テストを実行します。本番JSONはfixtureにしません。CLIの成功／失敗、ハッシュとサイズ、構造差分、予約差分、秘密値の非出力、欠損・不正入力、パス・特殊ファイル拒否を検証します。既存PR CIが実行し、手動Actions起動は不要です。
