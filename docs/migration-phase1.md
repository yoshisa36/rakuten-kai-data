# 運用データ分離：第1段階

## この変更の範囲

本番JSON、GAS、既存workflow、予約登録スクリプト、送信設定は変更しません。新しいリポジトリは作成しません。PRの既存CIで固定データの単体テストだけを実行します。自動返信OFFを維持します。

## テストの分離

JSON整合性6件と予約登録6件の入力を `tests/fixtures/` の人工データへ移しました。鮮度監視9件は既存の固定時刻・模擬データを継続使用します。単体テストは本番JSONや `batches/` を読みません。新規テストは保存先の互換性、JSON比較、予約ID・投稿済み状態保持、重複拒否、409再試行、401/403停止を検証します。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 tests/run_offline.py
```

ネットワークガードは読み込み前から有効です。HTTP処理のテストも `urlopen` または `request` をモックします。任意の子プロセスを隔離するサンドボックスではありません。PRのChecksで全テストの成功を確認します。本番の鮮度や投稿成功はこのCIの判定対象ではありません。

## 楽天監視の参照元設定

監視は入力を読み取るだけであり、保存先へ書き込みません。移行後のJSONを指定できるよう `--url` を追加しました。設定の優先順位は次のとおりです。

1. `--file` が指定された場合、そのファイルを読みます（従来と同じ）。
2. `--file` がない場合、`--url` のHTTPS参照先を読みます。
3. 両方未指定なら従来の `yoshisa36/rakuten-kai-data/main/rakuten-affiliate.json` を読みます。

URLにはユーザー名・パスワード・トークンを含めないでください。今回は認証付き参照を追加していません。非公開データへの対応は別設計です。既存workflowは `--file rakuten-affiliate.json` のままで、実行経路・スケジュール・権限を変更していません。終了コード0=正常、1=鮮度等の異常、2=入力等の監視エラーも維持します。この準備のために監視コマンドを外部URLへ実行する必要はありません。

## 予約登録先：設計のみ

今回は `scripts/register_threads_queue.py` を一切変更せず、対象リポジトリの固定値、既定main、Contents API、承認条件、書き込み後検証を維持します。代替リポジトリを選ぶCLIや環境変数はまだありません。

将来の案は `--repository owner/name` を追加し、未指定時は現行値を維持することです。対象はGitHub APIの固定ホスト内に限定し、認められたリポジトリ・ブランチを明示します。GET、PUT、409時の再GET、保存後照合のすべてで同じ対象を使い、拒否時に旧保存先へ自動フォールバックしません。認証はデータ専用に分離し、コード用 `GITHUB_TOKEN` で別リポジトリへ書けるとは仮定しません。このAPI設計の実装・許可先設定・実通信は次段階の別PRです。

既存の `register(api, batch, now)` はAPIを差し替え可能なので、今回はFakeAPIだけで重複・409・認証拒否・状態保持を確認します。これは代替リポジトリへの実登録や疎通の検証ではありません。

## 比較契約

`tests/migration_helpers.py` はテスト専用です。入力JSONの重複キー・非標準数値を拒否し、整形やオブジェクトのキー順を無視して比較します。配列順、本文、ID、承認、日時、未知フィールドは保持し、差異を検出します。ファイルや外部サービスを読み書きする移行ツールではありません。

将来の複製検証では、同一コピー元コミットとコピー先コミットを対応付け、初回はバイト単位ハッシュも比較します。コピーのためにupdatedAtを書き換えません。GAS側の取り込み済み・投稿済み状態はGitHub JSON比較だけでは確認できず、別途照合が必要です。

## 小さな段階と実施条件

1. **今回**: fixture分離、監視の互換設定、オフライン比較・失敗テスト、手順書。Draft PRのCIで確認。
2. **棚卸し**: GASソース、更新元・参照元、トリガー、認証の権限範囲、予約重複防止・状態保存場所を読み取り専用で確認。秘密値は記録しない。
3. **別PR**: 予約保存先の設定化とテストを実装。既定先・本番設定は維持。
4. **別途承認する移行**: 新データリポジトリ作成、限定認証、旧→新の一方向複製・比較。投稿処理は並行起動しない。
5. **切り替え**: 副作用のない参照元から順次変更。予約は重複防止・状態継承を確認後、処理境界で最後に切り替える。正本と書込主体は各ファイル群で一つ。
6. **保護**: コード側への運用書込みがなくなってからmainのPR・CI必須化。

ID欠落、状態不一致、認証拒否、更新周期の欠落があれば切り替えを保留します。切り戻し時は新側だけの正当な更新とGAS側の投稿済み状態を照合し、古いキューの単純復元や自動再登録を行いません。現時点ではGAS実装が未確認のため、無停止・二重送信防止を保証したとは扱いません。
